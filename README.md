# Анализ шахматных партий с Lichess

Курсовой проект по курсу «Большие данные» (НоДиАБоИ).

**Участники:** Поляков Вячеслав, Юдин Пётр, Инюшин Михаил, гр. 5040102/60201

**Источник данных:** https://database.lichess.org/ — официальные помесячные PGN-дампы партий (лицензия CC0, открытый доступ без авторизации).

## Задачи анализа
1. Анализ популярности дебютов и её динамики по годам/месяцам
2. Зависимость результата партии от дебюта и разницы рейтингов соперников
3. Сравнение статистики по контролям времени (блиц/рапид/классика)
4. Анализ частоты грубых ошибок в зависимости от рейтинга игрока
5. Предсказание исхода партии по дебюту и рейтингам игроков

## Структура
```
scripts/download_data.py   — скачивание сырого дампа из источника
scripts/parse_pgn.py       — потоковый разбор PGN (.zst) в CSV, по строке на партию
scripts/analyze_basic.py   — первичная аналитика: сводка и графики
scripts/analyze_speed.py   — задача 3: сравнение блица, рапида и классики
scripts/analyze_blunders.py — задача 4: ошибки и ACPL в зависимости от рейтинга
scripts/petr_analysis_common.py — общие функции анализов Петра
tests/test_parse_pgn.py    — проверка парсера: python -m tests.test_parse_pgn
tests/test_petr_analysis.py — проверки задач 3–4
data/raw/                  — сырые .pgn.zst дампы (не хранятся в git)
data/processed/            — разобранные CSV (не хранятся в git)
reports/                   — результаты аналитики: summary.md и графики
reports/speed/             — задача 3: таблицы, графики и выводы
reports/blunders/          — задача 4: таблицы, графики и выводы
```

## Запуск
```bash
pip install -r requirements.txt
python scripts/download_data.py 2013-01                          # скачать дамп(ы) в data/raw/
python scripts/parse_pgn.py data/raw/lichess_2013-01.pgn.zst     # -> data/processed/games_2013-01.csv
python scripts/analyze_basic.py data/processed/games_2013-01.csv # -> reports/
```
Месяцы передаются аргументами (`python scripts/download_data.py 2013-01 2014-01`), уже скачанные пропускаются.
Загрузка идёт во временный `.part`-файл, поэтому оборванная загрузка не оставляет битый файл.
Для больших дампов в `parse_pgn.py` есть `--max-games N`: файл читается потоком и обработка останавливается после N партий.

## Поля CSV
`game_id, speed, event, result, utc_date, utc_time, white_elo, black_elo, white_diff, black_diff, eco, opening, time_control, base_sec, inc_sec, termination, n_plies, has_eval, has_clock, moves_6`

Для задачи 4 (заполнены только у партий с оценками Stockfish, иначе пусто):
`white_acpl, black_acpl` – средняя потеря оценки за ход (сотые пешки), `*_evaluated` – сколько ходов учтено, `*_inaccuracies / *_mistakes / *_blunders` – число ходов с потерей [50, 100) / [100, 200) / ≥200 соответственно (категории не пересекаются), `evals` – оценка после каждого полухода через запятую (с точки зрения белых, сотые пешки, мат = ±1000).

Имена игроков не сохраняются: для задач проекта они не нужны.

## Задачи 3–4 — Юдин Пётр

### Подготовка

Из корня репозитория, Python 3.10 или новее:

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell вместо предыдущей команды:
# .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python scripts/download_data.py 2013-01
python scripts/parse_pgn.py data/raw/lichess_2013-01.pgn.zst
python -m tests.test_parse_pgn
```

Скрипты загрузки и парсинга используются без изменений. Сырые PGN, CSV партий,
виртуальное окружение и временная база дедупликации не добавляются в git.
Временная база создаётся в системном временном каталоге и удаляется после запуска.

### Одна команда на задачу

Черновики на полном месяце 2013-01:

```bash
python scripts/analyze_speed.py data/processed/games_2013-01.csv
python scripts/analyze_blunders.py data/processed/games_2013-01.csv
```

CSV полного датасета, полученные от Вячеслава, сохраните в отдельную папку
`data/processed/full/`. Поместите туда только файлы общего набора и запустите:

```bash
python scripts/analyze_speed.py "data/processed/full/*.csv"
python scripts/analyze_blunders.py "data/processed/full/*.csv"
```

Можно перечислить несколько файлов через пробел. Шаблон в кавычках раскрывается
самим скриптом, включая Windows. Следует передавать только месяцы выбранного
датасета. Скрипты читают необходимые столбцы блоками по 100 000 строк;
полные таблицы партий и `evals` в память не загружаются. Идентификаторы уже
учтённых партий хранятся во временной SQLite-базе на диске.

Повторы `game_id` удаляются между блоками и файлами; используется первая
завершённая запись в порядке аргументов (внутри шаблона — по имени файла).
При конфликтующих версиях одного CSV сначала передавайте нужную версию.
Отчёты перезаписываются в своих каталогах; результаты `analyze_basic.py` не затрагиваются.

### Что рассчитывается

**Задача 3.** Число и доля партий, доли побед белых/чёрных и ничьих,
результативность (доля побед), средний счёт белых, средняя длина, медиана и
квартили длины, способы завершения из `Termination`, средние/медианы/квартили
рейтингов обеих сторон, средняя абсолютная разница рейтингов. Дополнительно
сохраняется сводка по месяцам и точные частотные распределения.

Длина измеряется **в полуходах**, а не минутах: текущий CSV не содержит
показаний часов. Тег `Normal` не позволяет разделить мат и сдачу.

По умолчанию контроль определяется по `t = base_sec + 40 * inc_sec`
([границы Lichess](https://lichess.org/faq#time-controls)):

| Контроль | t, секунд на одного игрока |
| --- | --- |
| Ультрапуля | 0 < t < 30 |
| Пуля | 30 ≤ t < 180 |
| Блиц | 180 ≤ t < 480 |
| Рапид | 480 ≤ t < 1500 |
| Классика | t ≥ 1500 |

В задачу 3 входят только блиц, рапид и классика. Для сравнения разных лет
используется единая классификация: историческая метка `classical` может
включать контроль, который сейчас относится к рапиду. Число расхождений с
исходной меткой записывается в отчёт. `--speed-source event` позволяет
использовать `speed` из PGN. Классификация не пересчитывает исторические рейтинги.

**Задача 4.** Белые и чёрные становятся отдельными наблюдениями
«игрок–партия» со своим рейтингом. Используются только пригодные метрики
партий с `has_eval=1`; пропуски не заменяются нулями.

- Частота грубых ошибок: `100 * sum(blunders) / sum(evaluated)`.
- ACPL с весом по числу ходов: `sum(acpl * evaluated) / sum(evaluated)`.
- Дополнительно: среднее число ошибок на участие в партии, средний ACPL
  по участиям, доля участий с ошибкой и полнота оценивания ходов.
- Разрезы: рейтинговая группа, контроль, месяц, цвет фигур; отдельные
  таблицы и график показывают покрытие исходной выборки оценками Stockfish.

По умолчанию задача 4 включает все известные контроли, в том числе пулю
и переписку. Для переписки используется исходная метка `correspondence`.
При необходимости ограничьте контроли: `--speeds blitz rapid classical`.
Рейтинговые интервалы имеют вид `[1200, 1400)`; ширина по умолчанию — 200.
В CSV остаются все группы; на графиках основных метрик показаны группы
с минимум 30 участиями и 100 оценёнными ходами. Это фильтр малых групп,
а не тест статистической значимости.

Ограничения: оценённые партии — не случайная выборка; повторные участия
одних людей нельзя выявить без идентификаторов игроков. Парсер обрезает
оценки до ±1000 cp, так же кодирует мат и исключает первый ход белых.
Исходные ACPL округлены до 0.1. Эти учебные показатели не обязаны совпадать
с классификацией ошибок на сайте Lichess. Причинные выводы не делаются;
для интерпретации сравнивайте группы внутри контроля и периода.

### Результаты и параметры

| Каталог | Содержимое |
| --- | --- |
| `reports/speed/` | `summary.md`, 5 PNG, сводка по контролям и месяцам, распределения и окончания в CSV |
| `reports/blunders/` | `summary.md`, 4 PNG, метрики по рейтингу/контролю/месяцу/цвету и покрытие в CSV |
| Оба каталога | `run_metadata.json`: входные файлы, их размеры, параметры, версии библиотек, число исключённых строк |

Все сводные CSV содержат числители и знаменатели метрик. Эти агрегаты
можно хранить в git; отдельные партии из `data/` — нельзя.
Если подходящих партий или оценок нет, скрипт сохраняет отчёт об отсутствии
данных и графики с пояснением; отсутствие оценок не выдаётся за отсутствие ошибок.

| Параметр | Назначение |
| --- | --- |
| `--out PATH` | Другой каталог отчёта |
| `--chunksize 50000` | Меньший блок чтения при ограниченной памяти |
| `--speed-source event` | Исходные метки контроля из PGN вместо расчёта по времени |
| `--rating-bin 100` | Ширина рейтинговой группы, только задача 4 |
| `--min-player-games 50` | Минимум участий в группе на графике задачи 4 |
| `--min-evaluated 500` | Минимум оценённых ходов в группе на графике задачи 4 |
| `--speeds blitz rapid classical` | Выбор контролей в задаче 4 |

### Проверка

```bash
python -m tests.test_parse_pgn
python -m unittest tests.test_petr_analysis -v
```

Проверяются границы контролей и добавление времени, правильные знаменатели,
взвешивание ACPL, независимый учёт сторон, интеграция с парсером, повторы между
файлами, одинаковые результаты при разных размерах блока, неверные метрики,
пустой CSV и отсутствие оценок. Дополнительные библиотеки для тестов не нужны.

Отчёты, включённые в эту ветку, построены на **всех 121 332 партиях дампа 2013-01**,
а не на полном многомесячном датасете команды. После получения его CSV нужно
повторить две команды с шаблоном выше и обновить отчёты.
Данные и результаты проверки на 29 октября описаны в
[заметке Петра](reports/petr_testing_notes.md).
Помесячные таблицы группируются по `utc_date`, а не по имени файла: в дампе
2013-01 есть пограничные записи с датой декабря 2012.
